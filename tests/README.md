# Матрица тестирования MVP

Минимальные сценарии перед сборкой .cfe:

1. Реализация на 100 RUB → создаётся одно obligation.
2. Повторное нажатие «Отправить» → тот же идемпотентный ключ, дубль не создаётся.
3. Поступление → организация становится debtor, контрагент creditor.
4. Нет сопоставления контрагента → понятная ошибка, HTTP не вызывается.
5. HTTP недоступен → документ 1С записывается, сообщение остаётся в outbox.
6. Retry после timeout → безопасный повтор по Idempotency-Key.
7. Candidate A→B→C отображается без автоматического исполнения.
8. Redirect на нового контрагента нельзя выполнить без явного «Согласовать».
9. Reject не создаёт settlement instruction.
10. pending/locked instruction не меняет состояние расчётов в 1С.
11. settled instruction на часть суммы → отражается только частичное исполнение.
12. credit note/корректировка не создаёт новый долг поверх исходного без правил Core.
13. Валюта документа сохраняется отдельно от валюты регламентированного учёта.
14. Две Организации в одной ИБ не видят настройки/очередь/обязательства друг друга.
15. Повторное входящее событие settlement не создаёт повторный документ отражения.

## Definition of Done
- Проверка расширения на целевом релизе БП 3.0.
- Нет HTTP в обработчиках записи типовых документов.
- Нет прямой записи производных состояний взаиморасчётов.
- Все команды UI работают с ролью Orbitas-пользователя без ПолныхПрав.
- Логи не содержат токены доступа.
- Есть сценарий восстановления после недоступности Orbitas Core.
