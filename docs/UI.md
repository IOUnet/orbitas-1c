# Интерфейс MVP в терминах 1С:Предприятия

## Раздел «Orbitas»

Основная команда: **Рабочее место Orbitas**.

### Страница «Подключение»
Поля:
- Организация
- Participant Passport
- Адрес сервера Orbitas
- Состояние подключения

Команды:
- **Создать паспорт**
- **Привязать существующий паспорт**
- **Проверить подключение**

### Страница «Обязательства»
Две группы:
- **Нам должны** — входящие obligations;
- **Мы должны** — исходящие obligations.

Колонки:
- Контрагент
- Исходный документ
- Сумма
- Остаток
- Валюта
- Срок
- Состояние Orbitas
- Obligation ID

### Страница «Найти взаимозачёт»
Команда **Найти взаимозачёт** запрашивает candidate paths у Orbitas Core.

Для пути `A → B → C` показывать:
- кто является текущим должником;
- наша роль в цепочке;
- кому предлагается направить платёж;
- сумма и валюта;
- какие обязательства затронуты;
- появляется ли новый контрагент по расчёту;
- срок действия предложения.

Никакого автоматического исполнения на этом экране нет.

### Страница «Предложения»
Для выбранного предложения:
- **Согласовать**
- **Отклонить**

Если redirect меняет получателя платежа, интерфейс должен явно показать нового получателя до подтверждения.

### Страница «Распоряжения на расчёт»
Колонки:
- Распоряжение
- Плательщик
- Получатель
- Сумма
- Валюта
- Срок
- Состояние Orbitas
- Отражено в учёте
- Документ отражения

Состояния:
`pending → locked → settled / expired / cancelled`.

**pending** и **locked** не являются оплатой.

### В формах «Реализация» / «Поступление»
Группа **Orbitas**:
- Obligation ID
- Состояние Orbitas
- Остаток Orbitas
- команда **Отправить в Orbitas**
- команда **Открыть в рабочем месте Orbitas**

## Формулировки, которых избегаем
Не использовать в пользовательском интерфейсе:
- «invoice graph»;
- «R/Q/S»;
- «smart contract lock»;
- «candidate path execution»;
- «on-chain settlement».

Это детали Orbitas Core. В 1С пользователь видит документы, обязательства, взаимозачёт, согласование и распоряжения на расчёт.
