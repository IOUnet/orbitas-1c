# Архитектура MVP

## Пользовательский поток

```
Реализация / Поступление
        ↓
Нормализация обязательства
        ↓
Очередь обмена Orbitas
        ↓
Orbitas obligation
        ↓
Найти взаимозачёт
        ↓
Предложение взаимозачёта
        ↓
Согласовать / Отклонить
        ↓
Распоряжение на расчёт
        ↓
pending → locked → settled | expired | cancelled
        ↓
Только после подтверждённого settled:
отражение исполнения штатным механизмом 1С
```

## Граница ответственности

### В 1С
- организация и её Participant Passport;
- сопоставление Контрагент ↔ Participant Passport;
- извлечение фактов из документов учёта;
- нормализация invoice-like документов в obligation DTO;
- durable outbox/inbox;
- интерфейс дебиторки/кредиторки Orbitas;
- показ candidate paths;
- явное согласие/отказ;
- показ распоряжений на расчёт;
- бухгалтерское отражение только подтверждённого исполнения.

### В Orbitas Core
- граф обязательств;
- поиск открытых путей A → B → C;
- policy/consent validation;
- R/Q/S;
- locks;
- формирование и lifecycle settlement instruction;
- финальная проверка исполнения.


## Ключевой бухгалтерский инвариант

Orbitas status и состояние расчётов 1С — разные оси состояния.

Пример:

| Orbitas | Учёт 1С |
|---|---|
| active | не оплачен |
| locked | не оплачен |
| settlement pending | не оплачен |
| settled | требует отражения фактического расчёта |
| cancelled | без изменения учёта |

Расширение не должно напрямую записывать производные итоги расчётов. Для production-адаптера отражение выполняется штатным документом/механизмом конфигурации после подтверждения факта исполнения.
